## v1.15.0 - 2026-10-06
### Minor
* `docker create` gains `--plugin` (repeatable, or comma-separated) to install Neo4j plugins such as `apoc` or `graph-data-science` in the new container via `NEO4J_PLUGINS`; the command's result lists them. Plugin names are lower-case letters, digits and hyphens, and a name the image does not know shows up in `docker logs <name>` when the container starts.
* Pressing Ctrl-C (SIGINT) or sending SIGTERM now stops a running command promptly: in-flight Aura requests and `--wait` polling are cancelled instead of running to completion, and the command exits with status 130 (143 for SIGTERM). A second Ctrl-C force-quits.
* `docker delete` can now remove the data volume that a `docker load` container leaves behind (`neo4j-cli-<name>-data`, which holds the loaded database): pass `--remove-volume`, or answer the new prompt on a terminal (default no). With `--yes --force` and no `--remove-volume` the volume is kept and the command to remove it later is printed. Only the volume the CLI created for that container is ever removed.
### Patch
* Aura commands no longer crash and exit 0 when the Aura API or its authentication endpoint cannot be reached, times out, or sends an unreadable response. They now report an error and exit 8 (upstream, retryable), and Aura commands reject a malformed API response with an error instead of crashing.
* An unexpected internal crash now exits with status 1 (it previously exited 0, so a failed command could look successful) and prints its diagnostic to stderr instead of stdout.
* A corrupt or unreadable `config.json` now produces a clear error naming the file (exit 1) instead of a crash.
* `docker create` no longer leaves a running container whose password is lost. A missing credential store, or a reserved or already-stored credential name (for example `desktop`), now fails before the container is created. If storing the credential fails after the container starts, the password is still shown with a warning; with `--no-print-password` and a generated password the container is removed and the command fails. `docker load` and `aura instance load` apply the same checks.
* `aura agent` commands now report a missing organization or project with the standard `no organization specified; set a default workspace ...` usage error (exit 2) instead of `required flag(s) ... not set`, and the `--organization-id` and `--project-id` flags are documented once on the `agent` group instead of on every subcommand.
* Aura commands now reject organization, project, agent, instance, GraphQL Data API, authentication-provider, virtual-graph, session, snapshot and customer-managed-key IDs that contain path or query characters (such as `/`, `..`, `?` or `#`), with a validation error, before sending any request.
* The `docker` commands now work when `docker` is aliased to podman. Listing containers (used by `docker create`, `list`, `get` and `load`) failed with a JSON parse error because podman reports container names and labels in a different shape.
* `aura graph-analytics session list` now returns all pages of sessions instead of only the first server-defaulted page, so sessions beyond that first page are no longer missing from the output.
