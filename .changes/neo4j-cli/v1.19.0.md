## v1.19.0 - 2026-10-23
### Minor
* New `neo4j-cli feedback` command group (`enable`, `disable`, `status`, `submit`, `register`) behind the `flag.feedback-command` feature flag (`NEO4J_CLI_FLAG_FEEDBACK_COMMAND=1` or `neo4j-cli config set flag.feedback-command true --rw`). Coding agents can send short reports about problems with `neo4j-cli` to the Neo4j team, only after a person agrees: `feedback enable --accept`, run by a person at a terminal (refused when a coding agent is detected or stdin is not a terminal), or accepting the question the registered feedback tool asks in Claude Code or Codex the first time an agent reports (a question left unanswered for 5 minutes sends nothing). Reports are checked locally and rejected, never trimmed, if they look like they contain queries, file paths, connection details, credentials or identifiers; every attempt is recorded locally. `enable` and `register` are writes (`--rw` under an agent); `disable` never needs `--rw`. `status` follows `--format`. `DO_NOT_TRACK=1` or `telemetry` set to false switches feedback off. The text of `feedback submit` is masked in command history, telemetry and crash output and is never saved by tee.
* The install scripts (`install-neo4j-cli.sh`, `install-neo4j-cli.ps1`) offer agent feedback when the installed build has the `neo4j-cli feedback` command: at a terminal they show what a report contains and ask `[y/N]` (default No); with no terminal, or when a coding agent runs them, they ask nothing and register the feedback tool with Claude Code and Codex without enabling anything. `NEO4J_CLI_SKIP_FEEDBACK_PROMPT=1`, `DO_NOT_TRACK=1` or telemetry turned off skips both, and a failure in this step never fails the install.
