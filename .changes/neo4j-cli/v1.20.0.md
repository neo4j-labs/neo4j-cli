## v1.20.0 - 2026-11-27
### Minor
* New `neo4j-cli k8s` command group behind the `flag.k8s-commands` feature flag (`NEO4J_CLI_FLAG_K8S_COMMANDS=1` or `neo4j-cli config set flag.k8s-commands true --rw`), for managing Neo4j on Kubernetes through the open-source Neo4j operator. This preview adds `k8s doctor`, which checks that kubectl (1.22 or newer) and helm (3.8 or newer) are on PATH, that the cluster answers, that it runs Kubernetes 1.35 or newer, and that kubectl is within one minor version of the server. It follows `--format`, accepts `--kubeconfig`, `--context` and `-n/--namespace`, and always exits 0 with `summary.ready` saying whether the setup is ready. The group shells out to the host kubectl and helm and is not available through the `neo4j-cli mcp` server.
* agent-context output now includes a read_only boolean on every command entry (false for commands that require --rw)
* Add --format jsonl: list output prints one compact JSON object per line, with no data envelope
* Add --limit to aura instance list: return at most that many instances, with a note on stderr when more exist
* aura instance delete accepts --dry-run: looks up the instance and prints dry_run, action, resource_type, resource_id and name without deleting; needs no --yes --force
### Patch
* agent detection now honours AI_AGENT and recognises Junie, GitHub Copilot, Cline and Antigravity, so those harnesses get agent-mode output and are classified as `agent`; a person typing in the Kiro IDE terminal is no longer treated as an agent, so write commands run there without requiring --rw
