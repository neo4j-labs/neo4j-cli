# `distribution/homebrew/` — `neo4j-cli` on Homebrew

Maintainer-facing notes for the Homebrew distribution channel. The formula
itself isn't checked into this repo — it's auto-generated by GoReleaser and
pushed to a separate tap repo on every stable `neo4j-cli` release.

For the end-to-end release lifecycle (changelog → Release PR → GitHub Release
→ Homebrew tap), see [`../../RELEASING.md`](../../RELEASING.md). This document
covers Homebrew specifics only.

## What this directory does

Nothing at runtime — Homebrew shipping is fully handled by GoReleaser's
built-in `brews:` block in [`.goreleaser.yaml`](../../.goreleaser.yaml). No
parallel publish script (unlike `distribution/npm/`, which fans out across 9
packages). This directory exists for documentation only.

## User install

```sh
brew install neo4j-labs/tap/neo4j-cli
```

That's it. `brew` adds the tap on first install and resolves the formula
from there. Subsequent `brew upgrade neo4j-cli` picks up new stable releases.

## Tap location

[`neo4j-labs/homebrew-tap`](https://github.com/neo4j-labs/homebrew-tap) — a
public repo that hosts `Formula/neo4j-cli.rb` (and any other neo4j-labs
formulas added later). GoReleaser commits the regenerated formula on each
stable release; the tap repo has no human-edited content under `Formula/`.

## Release cadence — stable only

The brew formula is **only** pushed for stable tags (`vX.Y.Z`). Prereleases
(`vX.Y.Z-alpha.N`, `-beta.N`, `-rc.N`) are gated by GoReleaser's
`skip_upload: auto` on the `brews:` block — the rest of the release
(GitHub Release, npm publish) still happens, only the formula update is
suppressed.

Alpha users opt in via npm:

```sh
npm i -g @neo4j-labs/cli@alpha
```

See [`../npm/README.md`](../npm/README.md) for npm dist-tag rules.

## Local dry-run

Before merging a change to the `brews:` block, render the formula locally:

```sh
make snapshot
```

GoReleaser writes the formula to `dist/homebrew/Formula/neo4j-cli.rb`. Inspect
`url`, `sha256`, `bin.install`, and the `test do` block. Optional sanity
check:

```sh
brew audit --strict --formula dist/homebrew/Formula/neo4j-cli.rb
```

`make snapshot` doesn't push — `--snapshot` mode never touches the tap repo
regardless of whether `HOMEBREW_TAP_GITHUB_TOKEN` is set.

## Manual recovery

If a release writes a broken formula (e.g. wrong `sha256` after an archive
re-upload), recovery is straightforward:

1. Hand-edit `Formula/neo4j-cli.rb` directly in the
   [`neo4j-labs/homebrew-tap`](https://github.com/neo4j-labs/homebrew-tap)
   repo on GitHub. Push the fix on `main`.
2. Users get the fix on their next `brew update && brew upgrade neo4j-cli`.

The next stable release of `neo4j-cli` will overwrite the formula, so any
hand-edits are temporary by design — fix the underlying issue (e.g. the
`brews:` block in [`.goreleaser.yaml`](../../.goreleaser.yaml)) before the
next release.

## Auth prerequisites

Push to the tap is authenticated by a short-lived GitHub App installation
token minted per release run — no long-lived PAT in CI.

**GitHub App** (one-time, configured at the org level):

- Owned by `neo4j-labs`.
- Installed on `neo4j-labs/homebrew-tap` only.
- Scope: `contents: write` on that repo.

**Repo secrets** (on `neo4j/cli`):

| Secret                          | Used by                             | For                                                                |
| ------------------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| `HOMEBREW_TAP_APP_ID`           | `release.yml` → `brew-token` step   | App ID input for `actions/create-github-app-token`                 |
| `HOMEBREW_TAP_APP_PRIVATE_KEY`  | `release.yml` → `brew-token` step   | Private key for the App; minted token is exposed to GoReleaser env |

The `Mint Homebrew tap token` step in
[`.github/workflows/release.yml`](../../.github/workflows/release.yml) calls
`actions/create-github-app-token` with `owner: neo4j-labs` and
`repositories: homebrew-tap`, then plumbs the resulting token into the
`Run GoReleaser` step as `HOMEBREW_TAP_GITHUB_TOKEN`. The `brews:` block in
`.goreleaser.yaml` reads it via `{{ .Env.HOMEBREW_TAP_GITHUB_TOKEN }}`.
