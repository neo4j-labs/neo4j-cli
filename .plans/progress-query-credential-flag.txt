================================================================================
TASK-001: Add --credential flag to query command and resolveConn integration
Date: 2026-05-06T12:00:00Z
================================================================================

Summary:
Added --credential persistent string flag to neo4j-cli query command. Updated
resolveConn() to handle the new flag: when set, the named credential is loaded
directly (skipping dotenv/env-var resolution), mutual exclusion with
--uri/--username/--password/--database is enforced, and --insecure can override
the credential's stored insecure value. Regenerated the skill bundle since the
flag table changed (required for TestGenerator_RoundTrip to pass). Also fixed
two pre-existing test hermiticity bugs where TestResolveConn_Precedence* and
TestResolveConn_DotenvWins* used afero.NewOsFs() and failed on machines with
real database credentials stored.

Files Changed:
- neo4j-cli/query/query.go (modified: added --credential persistent flag)
- neo4j-cli/query/connect.go (modified: --credential branch in resolveConn, dotenv load deferred past credential branch)
- neo4j-cli/query/connect_test.go (modified: 6 new test functions, 2 existing tests migrated from OsFs to memFs)
- neo4j-cli/internal/skill/bundle/references/query.md (modified: regenerated to include --credential flag)

Key Decisions:
- loadEnvFile is now called only in the non-credential branch (after the early return), not unconditionally at the top of resolveConn. This matches the PRD spec that --credential should "ignore .env/env-var connection values."
- insecureExplicit is computed at the very top of resolveConn (before the --credential branch) since both branches need it.
- Tests use namedCredJSON() helper (no default-credential set) to cleanly test the --credential flag path independently from the auto-detect default-credential path.
- Two existing tests migrated to use testfs.GetTestFs+memFs to be hermetic against real stored credentials on the dev machine.
