TASK-006: Integrate default database credential into neo4j-cli query connection resolution
Date: 2026-05-06T05:00:00Z
================================================================================

Summary:
Updated resolveConn() in neo4j-cli/query/connect.go to integrate the stored
default database credential into query connection resolution. When no connection
params are explicitly provided (via flags, env vars, or dotenv), the stored
default database credential is used. A stored credential with insecure:true
skips TLS verification. Partial explicit overrides (1-3 of 4 params) when a
stored credential exists produce a descriptive error. Existing behavior when no
stored credential is present is fully preserved.

Also changed flag-reading to use f.Changed (explicit set detection) instead of
flagString(cmd, "uri") != "" — this is more correct and required for tracking
whether params were explicitly provided.

Files Changed:
- neo4j-cli/query/connect.go (modified — credential integration, flag-reading via f.Changed, switch-based dispatch)
- neo4j-cli/query/connect_test.go (modified — added testfs import, 6 new tests, 2 helpers)

Key Decisions:
- All-or-nothing validation is only enforced when a stored credential exists; without a stored credential, the original behavior (partial params + built-in defaults) is preserved, keeping backward compatibility with existing tests
- Flag-reading uses f.Changed instead of flagString() != "" for correct "was this explicitly set" detection
- insecureExplicit tracks whether --insecure flag was Changed so stored credential's insecure value is only applied when the flag was not explicitly passed
- storedCredJSON helper uses string concatenation for test JSON (suitable for controlled test inputs)
