# PRD: CLI-228 — Register generated Docker passwords as secrets

## Overview

`neo4j-cli docker create` mints a 16-byte base64 URL-safe password and renders it into its output, but never registers it with `clievents.RegisterSecretValue`. `common/clievents.RedactText` — the CLI's single text-level redactor — is **shape-based**: it matches `key=value` assignments, quoted JSON fields, connection-URI userinfo, and `Bearer`/`Basic` headers, but not layouts that put a value on a different line from its key. That limitation is documented in the `RedactText` doc comment itself (`common/clievents/redact.go:240-246`), which states that a secret printed only as a table cell is caught *solely* by the `RegisterSecretValue` literal-match pass.

The identical unregistered-generated-secret bug exists in `docker load`: `generatePassword()` at `load.go:445-453` is minted for the new-container path (`load.go:344-350`, inside `LoadDumpIntoNewContainer`) and rendered at `load.go:173`.

This feature makes any password the CLI *generates* for a Docker container register itself as a literal secret at the moment it is minted, from a single auditable code point, so every present and future capture surface scrubs it regardless of output format. Human-facing stdout is byte-identical.

### Which formats actually leak (measured, not assumed)

Running each rendering shape through `RedactText` with a representative 22-char base64 password gives:

| Surface | Shape | Leaks today? |
|---|---|---|
| `--format table` | box-drawing cell, value on its own line | **yes** |
| `--format toon` | `[1]{username,password}:` header + CSV value line | **yes** |
| `--format json` | `"password":"<v>"` | no — caught by `textJSONFieldRe` (`redact.go:223`) |
| `--ephemeral` `.env` blob | `NEO4J_PASSWORD=<v>` | no — caught by `textAssignmentRe` (`redact.go:214`; unanchored, so it matches the `PASSWORD=` substring inside `NEO4J_PASSWORD=`) |

So the gap is **`table` and `toon` only**. `toon` matters most: it is the **agent-harness default** (`output.ResolveOutput` → `IsAgent` → `toon`), i.e. precisely the format CLI-218's `mcp serve` will emit.

### Present-day blast radius (stated precisely)

Two surfaces consume `RedactText`, and neither is currently reachable with this password:

- **tee-on-failure** (`common/tee/tee.go:112`) runs only when `cmd.Execute()` returns non-nil (`neo4j-cli/main.go:156-176`). In both leaves the password reaches stdout as the *last* action before `return nil` (`create.go:412` ephemeral blob, `create.go:436` `PrintBodyMap`, `load.go:177`), and the only `PersistentPostRunE` in the tree is `quip.Hook`, which always returns nil (`neo4j-cli/internal/quip/quip.go:146`). The `--wait` failure at `create.go:392` fires *before* any print. So no failing invocation produces a tee file containing the generated password.
- **`--debug`** never carries it: `debugInvocation` (`client.go:174-191`) emits argv plus env-var **NAMES only** — values are deliberately never emitted — and the password travels solely as `NEO4J_AUTH=neo4j/<pw>` in `cmd.Env` (`create.go:359`, `load.go:417`), never argv.

This work is therefore **defense-in-depth for the existing surfaces** and a **real leak closure for the MCP surface**: on the unmerged CLI-218 branch (`oskar/cli-218-mcp-server`, local to `~/Development/neo4j-cli-2`, not pushed to origin), tool output is passed through `sanitize` (`RedactText` + `StripControl`) into a `CallToolResult` that is copied into a model's context and uploaded to the host. There, the full stdout of a **successful** `docker create` in `toon` is what gets captured. `mcp/result_test.go:160-191` on that branch pins the JSON-shaped path and documents the table-cell gap as deliberately deferred to `create.go` — which is this PRD.

## Goals

- Every Docker container password **generated by the CLI** is registered as a literal secret before it can reach any output surface.
- Exactly **one** mint point covers `docker create`, `docker load`, and `aura instance load --stage docker` (which reaches `docker.LoadDumpIntoNewContainer`).
- Eliminate the duplicated password-generation logic currently present in both `create.go` and `load.go`.
- Human-facing CLI output remains byte-identical — an operator in a terminal still sees the generated password exactly as today.
- Make the invariant discoverable, so a future contributor neither re-inlines `randSource` + base64 in a new leaf nor widens registration to operator-supplied passwords.

## Non-Goals

- Making `RedactText` table- or TOON-aware. The shape-based design and its documented limitation stay as-is; `RegisterSecretValue` is the intended mechanism for this class of secret.
- Registering an **operator-supplied** `--password`. See REQ-F-006 and Technical Considerations.
- Changing what normal (non-captured) CLI output contains, in any format.
- Any change to the MCP layer. It does not exist in this repository.
- Adding a changie changelog entry (see REQ-NF-003).
- Bounding or pruning the `knownSecrets` registry (see the CLI-218 follow-up note in Technical Considerations).
- Backfilling the missing test for the unpinned `instance/create_core.go:114` registration.
- `desktop dbms load`'s unregistered operator-prompted password (pre-existing asymmetry vs. `desktop/dbms/create.go:221`; user-supplied, not generated).

## Requirements

### Functional Requirements

- REQ-F-001: A new file `neo4j-cli/internal/subcommands/docker/password.go` owns all password minting for the docker package. It receives, moved verbatim, `randSource` (from `create.go:54-57`), `generatedPasswordBytes` (from `create.go:67-70`), and `generatePassword()` (from `load.go:445-453`). It carries the Neo4j copyright header (CI `addlicense`).
- REQ-F-002: `generatePassword()` calls `clievents.RegisterSecretValue(pw)` on the minted value **before returning it**, so registration precedes every possible use.
- REQ-F-003: `docker create` replaces its inline generation (`create.go:286-296`) with a `generatePassword()` call. `err` is already declared in the `RunE` closure at `create.go:193`, so this is a plain assignment with no shadowing — mirroring `load.go:344-350`.
- REQ-F-004: `docker load`'s duplicate `generatePassword` definition (`load.go:445-453`) is deleted. Its call site at `load.go:344-350` needs no change and inherits registration.
- REQ-F-005: The error message is unified on `docker: generate password: %w`, owned by the helper. This replaces `docker create: generate password: %w` (`create.go:293`) and `generate password: %w` (`load.go:450`). Neither string is asserted by any test or referenced in any doc, and the path is only reachable if `crypto/rand` fails; the change is intentional and should be called out in review.
- REQ-F-006: An operator-supplied `--password` is **not** registered. This follows structurally from placing registration inside `generatePassword()`: both leaves only call it when the resolved password is empty.
- REQ-F-007: The generated password continues to be rendered exactly as today in all formats — the table/JSON/TOON row (`create.go:433`, `load.go:173`) and the `--ephemeral` `.env` blob (`create.go:404-413`) — and `--no-print-password` continues to suppress it (`create.go:432-435`).
- REQ-F-008: After a `docker create` or `docker load` run that generated a password, `clievents.RedactText(<captured stdout>)` does not contain that password, for `--format table` and `--format toon` (the formats that leak today) as well as `json`.
- REQ-F-009: `AGENTS.md:127` (the `RedactText` bullet in "Secrets / Redaction") records that the shape-based gap covers TOON rows as well as table cells, and that `docker/password.go` `generatePassword()` is the single registering mint point for docker container passwords.
- REQ-F-010: The `RedactText` coverage note at `common/clievents/redact.go:240-246`, which currently names only `aura instance create` as a registering caller, also names `docker create` / `docker load`. Comment-only, zero behaviour change.

### Non-Functional Requirements

- REQ-NF-001: No new module dependency. `clievents` is already a `docker`-package dependency via `client.go:21`.
- REQ-NF-002: Imports must be corrected or the package will not compile. `create.go` loses `"crypto/rand"` (`:8`), `"encoding/base64"` (`:9`) and `"io"` (`:12`) — after the extraction its only uses were the moved lines 57, 292 and 295 (line 530 is a comment). `load.go` loses `"encoding/base64"` (`:8`, only use was line 452) but **keeps** `"io"` (still used at `:283, :286, :470, :518`). The new `password.go` imports `crypto/rand`, `encoding/base64`, `fmt`, `io`, and `clievents`.
- REQ-NF-003: No changie changelog entry. Per AGENTS.md, entries state only observable user-facing impact and must be verified against diffed output; here `table`/`toon`/`json` stdout is byte-identical before and after, tee-on-failure is unreachable for these leaves, and `--debug` never carried the value. The user-facing statement belongs on CLI-218, where the MCP tool-result surface makes it observable.
- REQ-NF-004: No `go generate` drift. `create.go`'s `Long`/`Example` (`create.go:137-179`) must not be touched — `neo4j-cli/internal/skill/bundle/references/docker.md:29,49` embeds that text. Prove it with `make generate-check`.
- REQ-NF-005: Registration must not corrupt parsed data. `execClient.runEnv` (`client.go:240-277`) returns **raw** `stdout.String()`; `redactString` is applied only to the non-zero-exit error message (`:274`) and the `--debug` argv echo (`:178`). The two post-redaction string matches — `classifyInspectError` (`:405`, `"no such "`) and `inspectExited` (`stop.go:157-159`) — are unaffected because `redactKnownSecrets` only `ReplaceAll`s the exact 22-char base64url value.
- REQ-NF-006: `make test`, `make fmt-check`, `make lint`, `make license-check` all pass.

## Technical Considerations

**Why a new `password.go` rather than `create.go` or `load.go`.** AGENTS.md's one-file-per-leaf rule (`AGENTS.md:25-29`) constrains cobra *leaf command bodies*, not package-internal helpers; this package already has noun-named non-leaf production files (`client.go`, `labels.go`, `bolt_ready.go`, `push_to_aura_helpers.go`). Leaving the helper in `load.go` would make `create.go` reach *forward* into a sibling leaf (every other cross-reference runs load → create). Putting it in `create.go` works but grows the package's largest non-test file and keeps `randSource` where it landed by accident. A file named `password.go` makes the actual invariant — "there is exactly one place docker passwords are minted, and it registers them" — discoverable, which is the point of the change.

**Why generation-time, not render-time.** The aura precedent registers inside its render helper (`instance/create_core.go:106-115`), obliging every render site to remember. Note the rationale is *not* "it covers the `.env` blob" — the blob is already shape-covered. Generation-time is right because it is unconditional (so `--no-print-password` and any future print site cannot regress), it is a single auditable point covering both leaves plus `aura instance load --stage docker`, and it is colocated with the mint. Ordering relative to printing is not a correctness concern for tee — tee redacts the whole captured buffer once at end of process (`neo4j-cli/main.go:187`) — but registering at the mint makes ordering moot everywhere.

**Why operator-supplied passwords stay unregistered.** `RegisterSecretValue` guards only against values shorter than 4 characters (`redact.go:163`), and `redactKnownSecrets` is a plain longest-first `strings.ReplaceAll`. A user-chosen password like `neo4j` (5 chars) would rewrite `neo4j://localhost:7687`, `neo4j:enterprise`, and `username: neo4j` to `***` across all captured output, mangling exactly the diagnostics tee exists to preserve. A supplied password is already known to whoever supplied it, and `clievents.RedactArgs` already scrubs it from argv/history/telemetry (`password` is in `secretFlags`).

**Test-registry semantics.** `knownSecrets` is a process-global, additive slice with no exported reset (`resetKnownSecrets` at `redact_test.go:349` is package-private to `clievents`). Tests may therefore only *add* registrations. `go test` builds one binary per package, so there is no cross-package bleed. Existing docker tests that assert the exact generated password in **raw** stdout stay green because `PrintBodyMap` writes straight to `cmd.OutOrStdout()` and no existing docker test routes stdout through `RedactText` (the package's only `RedactText` reference is `client.go:66`, exercised in `client_test.go` with fixed cases that cannot contain a 22-char base64 value). The one real ordering hazard is a *negative* assertion being broken by an earlier test in the same package registering a substring of the asserted text — hence the collision-proof literal in the explicit-password test. The registry is `sync.RWMutex`-guarded and additive, so no `-shuffle` or parallelism concern.

**Test seam.** `create_test.go:34` already defines `constantReader` and swaps `randSource` for determinism (`create_test.go:176-180`). Bytes `0x10, 0x42, 0x55, 0x66, 0x77, 0x88, 0xAB, 0xCD, 0xEF` are taken; `0x01–0x05` are free. Use distinct values so each test registers a unique literal.

**Follow-up for CLI-218, not a blocker here.** `knownSecrets` is unbounded and never pruned, and `redactKnownSecrets` does a `sort` plus one full-output `ReplaceAll` pass per entry on *every* `RedactText` call. In a one-shot CLI process N ≤ 2. In a long-lived `mcp serve` process, N grows by one per `docker create`/`docker load` tool call and every later redaction pays O(N) full-output scans. Worth logging on CLI-218.

**Verification boundary.** The Linear ticket's acceptance check ("a `docker create` through the MCP executor with `--format table` produces a `CallToolResult` that does not contain the generated password") cannot be exercised here — there is no MCP layer in this repository. The gating evidence is REQ-F-008's unit tests; the MCP end-to-end check is a follow-up once `oskar/cli-218-mcp-server` rebases onto main.

## Acceptance Criteria

- [ ] `password.go` exists with the copyright header and owns `randSource`, `generatedPasswordBytes`, and `generatePassword()`; the helper registers via `clievents.RegisterSecretValue` before returning.
- [ ] `create.go`'s inline generation and both moved declarations are gone; `"crypto/rand"`, `"encoding/base64"`, `"io"` removed from its imports; `Long`/`Example` untouched.
- [ ] `load.go`'s duplicate `generatePassword` is gone; `"encoding/base64"` removed, `"io"` retained; `load.go:344-350` unchanged.
- [ ] `TestGeneratePassword_RegistersSecretValueForRedaction` (new `password_test.go`) — asserts the returned value matches the expected base64 for a deterministic `randSource`, that `RedactText(pw) == "***"`, and that it is scrubbed inside a synthetic table cell (`"│ "+pw+" │"` → `"│ *** │"`) to pin shape-independence.
- [ ] `TestGeneratePassword_RandSourceError_Wrapped` (new) — injects a failing reader; asserts `errors.Is` the sentinel and that the message contains `generate password`. Closes a real existing gap: no test in the repo injects a failing `randSource` today.
- [ ] `TestCreate_GeneratedPassword_ScrubbedFromRedactedCapture` — table-driven over `table`, `toon`, `json`. For each: raw stdout **still contains** the password (human output unchanged), `RedactText(stdout)` does **not**, and contains `***`. Fails pre-fix on `table` and `toon`; `json` passes both ways and documents that.
- [ ] `TestCreate_Ephemeral_GeneratedPassword_ScrubbedFromRedactedCapture` — `.env` blob path. Its comment must state honestly that this **passes pre-fix too** (the blob's `NEO4J_PASSWORD=` is shape-caught); it is a regression guard for the blob path, not a pin of this fix.
- [ ] `TestCreate_ExplicitPassword_NotRegisteredAsSecret` — with a distinctive literal such as `cli228-operator-supplied` (**not** `mysecret`, already used at `create_test.go:299`), asserts `RedactText(<literal>) == <literal>`, pinning REQ-F-006 so a future widening is conscious.
- [ ] `TestLoad_NewContainer_GeneratedPassword_ScrubbedFromRedactedCapture` — second-site pin; `load_test.go` currently never swaps `randSource`, so add a deterministic one. Same contains / not-contains pair with `--format table`.
- [ ] Existing docker tests asserting the exact generated password in raw stdout remain green, unmodified.
- [ ] `AGENTS.md:127` extended per REQ-F-009; `common/clievents/redact.go` coverage note extended per REQ-F-010.
- [ ] `make test`, `make fmt-check`, `make lint`, `make license-check` pass, and `make generate-check` shows zero skill-bundle drift. No changie entry added.

- Registering operator-supplied passwords anywhere in the CLI.
- Any MCP-layer code, tests, or the ticket's `CallToolResult` acceptance check (not runnable in this repo).
- A changie changelog entry.
- Bounding/pruning the `knownSecrets` registry or optimising `redactKnownSecrets`.
- Backfilling a test for the unpinned `instance/create_core.go:114` registration.
- `desktop dbms load`'s unregistered operator-prompted password.

## Open Questions

None. Scope (both `docker create` and `docker load`) and the no-changelog decision were confirmed with the user during planning. This PRD supersedes the earlier planning notes on three points that were corrected by verification against the source: the `.env` blob and `--format json` are already shape-covered (so `table`/`toon` are the only leaking formats), `--debug` never carried the password, and the helper lands in a new `password.go` rather than in `create.go`.
