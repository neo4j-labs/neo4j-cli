TASK-005: Wire credential storage and context-aware failure warnings into RunE
Date: 2026-05-07T03:00:00Z
================================================================================

Summary:
Wired credential storage into `RunE` in `create.go`. After a successful API
response, when `--no-credential-storage` is not set, the code:
1. Extracts `id`, `username`, `password`, and `connection_url` from the response map.
2. Calls `baseCredentialName` + `resolveCredentialName` to determine the storage name.
3. Injects `credential_name` into the `instance` map so it appears in output.
4. Calls `cfg.Credentials.Dbms.Add(...)` to persist the credential.
5. On failure, emits a context-aware warning to stderr (two variants based on
   `--no-credential-print`), then continues with exit 0.
Storage always occurs before the `--await` polling block.

Updated all existing tests that check JSON output to include `"credential_name"`
in their expected output (six tests updated: free, professional, vector-optimized,
CMK, config-tenant, and await variants).

Files Changed:
- neo4j-cli/aura/internal/subcommands/instance/create.go (modified: added credential storage block in RunE)
- neo4j-cli/aura/internal/subcommands/instance/create_test.go (modified: updated 6 existing test expected outputs + await test)

Key Decisions:
- Used `//nolint:errcheck` on `fmt.Fprintf` to stderr — write errors are not actionable for warning messages.
- Injecting `credential_name` into the `instance` map (before `NewSingleValueResponseData`) means JSON output automatically includes it; no special-casing needed for the JSON path.
- `resolveCredentialName` is called even on storage failure path (in case Add fails for a collision reason, the resolved name is still shown); this is consistent — the name is resolved and injected first, then Add is called.
