TASK-002: Implement PreRunE validation for new flag combinations
Date: 2026-05-07T00:00:00Z
================================================================================

Summary:
Extended the existing `PreRunE` in `create.go` with three validation guards:
(a) `--credential-name` and `--no-credential-storage` are mutually exclusive;
(b) explicit `--credential-name ""` (empty string) is rejected;
(c) `cfg.Credentials.Dbms == nil` (without `--no-credential-storage`) returns
a clear error directing the user to `--no-credential-storage`.

Finalize phase addressed two issues from the code review:
1. Added `TestCreatePreRunERejectsNilDbms` — a standalone (non-table-driven) test
   that constructs a `clicfg.Config` with credentials JSON containing `"dbms": null`,
   which causes `Credentials.Dbms` to be nil after JSON unmarshal. The test calls
   `cmd.PreRunE` directly (bypassing `ExecuteCommand`) so it exercises the guard
   without requiring a live HTTP server.
2. Replaced `assert.Empty(t, helper.PrintErr())` with `helper.AssertErr("")` in the
   table-driven `TestCreateCredentialFlagValidation` loop, dropping the direct
   `testify/assert` import in favour of `testify/require` (used by the new test).

Files Changed:
- neo4j-cli/aura/internal/subcommands/instance/create_test.go (modified: added
  TestCreatePreRunERejectsNilDbms, replaced assert.Empty with helper.AssertErr(""),
  swapped assert import for require)

Key Decisions:
- Used credentials JSON `"dbms": null` to produce a nil Dbms via standard
  `clicfg.NewConfig` rather than constructing a Config struct literal, keeping the
  test closer to the real production path.
- Called `cmd.PreRunE(cmd, nil)` directly (after setting required flags) to avoid
  the write-gate middleware and HTTP server setup that `ExecuteCommand` introduces.

TASK-003: Implement credential name generation and collision resolution helpers
Date: 2026-05-07T01:00:00Z
================================================================================

Summary:
Added two unexported helper functions in a new `credential_helpers.go` file in
the `instance` subcommand package, along with matching white-box unit tests in
`credential_helpers_test.go`.

- `baseCredentialName(instanceID, customName string) string`: returns `customName`
  when non-empty, else `<instanceID>-default`.
- `resolveCredentialName(dbms dbmsGetter, base string) string`: walks through
  `base`, `base-1`, `base-2`, … until `dbms.Get` returns an error (name free).

A minimal `dbmsGetter` interface is defined locally so the helper can be tested
with a stub without importing production FS or credential storage.

Files Changed:
- neo4j-cli/aura/internal/subcommands/instance/credential_helpers.go (created)
- neo4j-cli/aura/internal/subcommands/instance/credential_helpers_test.go (created)

Key Decisions:
- Defined `dbmsGetter` as `interface { Get(name string) (*credentials.DbmsCredential, error) }`
  which matches `*DbmsCredentials.Get` exactly, enabling direct use in RunE later.
- White-box test file uses `package instance` (not `instance_test`) to access
  unexported functions directly.
- `stubDbmsGetter` uses a `map[string]bool` of taken names for simple, legible tests.
- All acceptance criteria (base name logic + at least 2 collision steps) are covered
  by table-driven tests.
