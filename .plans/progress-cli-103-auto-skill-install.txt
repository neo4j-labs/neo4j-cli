Date: 2026-05-14T00:00:00Z
================================================================================

Summary:
Added a `postinstall` npm lifecycle hook to the `@neo4j-labs/cli` package template.
When `NEO4J_CLI_AUTO_INSTALL_SKILL=1` is set, `npm install -g @neo4j-labs/cli`
automatically runs `neo4j-cli skill install --rw` after binary placement. Any
failure is silently suppressed so npm install is never aborted.

Files Changed:
- distribution/npm/cli/bin/postinstall.js (created — Node.js postinstall hook script)
- distribution/npm/cli/package.json.tmpl (modified — added scripts.postinstall and postinstall.js to files array)
- distribution/npm/publish.sh (modified — copies postinstall.js to wrapper build dir)

Key Decisions:
- Implemented postinstall logic in a separate `bin/postinstall.js` file (not inline in package.json scripts) to keep the logic readable and testable
- Used `process.execPath` to invoke the shim so the same Node.js binary runs both scripts
- Used `spawnSync` with `{ stdio: 'inherit' }` for consistent output passthrough
- Always exits 0 at end of postinstall.js — non-zero exit from skill install is not propagated
- `postinstall.js` does NOT need chmod +x since it's invoked via `node bin/postinstall.js`

TASK-006: Add bats-core behavioral tests for install-neo4j-cli.sh
Date: 2026-05-15T00:00:00Z
================================================================================

Summary:
Created bats-core behavioral tests covering the NEO4J_CLI_AUTO_INSTALL_SKILL
feature in install-neo4j-cli.sh. Tests use a complete stub environment (curl,
tar, sha256sum, shasum, uname, sudo, neo4j-cli) injected via PATH prepending.
All 4 test cases pass on macOS (bats 1.13.0). shellcheck passes with no warnings.

Files Changed:
- distribution/installation-scripts/tests/install-neo4j-cli.bats (created — bats test suite with 4 test cases)

Key Decisions:
- The installer monolith cannot be partially sourced, so all external commands
  are stubbed via a STUBS_DIR prepended to PATH. This includes curl, tar,
  sha256sum, shasum, uname, and sudo.
- The curl stub for the checksums file writes a fake sha256 line matching the
  archive filename (derived from the checksums filename) so grep succeeds. The
  uname stub always returns Linux/x86_64, coordinating with the checksums stub.
- The tar stub creates a recording neo4j-cli binary (not just a blank file) that
  appends to STUB_CALLS (exported env var) and respects NEO4J_CLI_STUB_EXIT.
  This ensures the mv'd binary (which overwrites our pre-seeded INSTALL_DIR stub)
  still records calls correctly.
- NEO4J_CLI_STUB_EXIT env var controls skill subcommand exit code, enabling
  test 3 (fail scenario) without rewriting the stub file per test.
- bats `run` prefix-env mechanism passes NEO4J_CLI_AUTO_INSTALL_SKILL into the
  child bash process; STUB_CALLS and INSTALL_DIR are also forwarded via
  run_installer's explicit env block.

Summary:
Created Pester v5 behavioral tests for the NEO4J_CLI_AUTO_INSTALL_SKILL guard
in install-neo4j-cli.ps1. Tests run the installer as a pwsh subprocess with all
heavyweight cmdlets (Invoke-WebRequest, Expand-Archive, Get-FileHash, Get-Content)
stubbed via function overrides written to a temp wrapper .ps1 file. A neo4j-cli.cmd

windows-latest CI is the gate.

Files Changed:
- distribution/installation-scripts/tests/install-neo4j-cli.Tests.ps1 (created — Pester v5 test suite with 4 test cases)

Key Decisions:
- Used neo4j-cli.cmd stub (not .ps1) because Windows resolves bare `& neo4j-cli`
  to .cmd/.bat before .ps1 when searching PATH — this ensures the stub is actually
  found and invoked by the installer's `& neo4j-cli skill install --rw` call.
- Passed callsFile path via NEO4J_CALLS_FILE env var (not embedded literal) to
  avoid escaping complexity with backslashes and quotes in nested strings.

  (not -Command) to eliminate all quoting/escaping issues with the large command block.
- Stub overwrites `Add-ToUserPath` to suppress registry PATH mutation in tests.
- Test wrapper uses `Set-StrictMode -Off` and `$ErrorActionPreference = 'Continue'`
  so stub gaps produce warnings rather than test failures.
