## Manual verification (live DB)
Requires a live Neo4j (e.g. `make run-neo4j` or `neo4j-cli docker create`); NOT run in CI/here.
1. Multi-read JSON array: `neo4j-cli query 'RETURN 1 AS a;
RETURN 2 AS b' --format json` -> expect a JSON array of two result envelopes in order.
2. Stacked table/toon: same two-statement read with `--format table` -> two table blocks separated by a blank line; `--format toon` -> array form.
3. --atomic rollback vs default persistence on a failing 2nd write:
   - Default: `neo4j-cli query --rw 'CREATE (:A);
THIS IS INVALID' ` -> first CREATE persists (verify `MATCH (:A) RETURN count(*)` > 0), error surfaces.
   - Atomic: clear, then `neo4j-cli query --rw --atomic 'CREATE (:A);
THIS IS INVALID'` -> whole tx rolls back (verify count == 0), error surfaces.
4. Single-statement parity: `neo4j-cli query 'RETURN 1 AS a'` and `... 'RETURN 1 AS a;'` -> output byte-identical to pre-feature single-statement output (single JSON object / single table), no `statement N:` prefixes.
