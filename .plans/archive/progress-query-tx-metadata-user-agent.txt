TASK-003: Drop txMetadata, document min version, add User-Agent-only changelog
Date: 2026-05-05T13:00:00Z
================================================================================

Summary:
End-to-end verification revealed Neo4j 5.x and 2025.x reject any v2 query
request that carries a txMetadata body field with HTTP 400 — the field is
only accepted from Neo4j 2026.04 onward (labelled new-2026.04 in the docs
source repo). To stay compatible with current production servers, the
txMetadata send site (added in task-001) and its lock-in tests (added in
task-002) are removed. The User-Agent header — which is harmless on every
server version — stays. A doc comment on runStatement records the deferral
and names Neo4j 2026.04 as the minimum server version, so a future
re-enable can land gated behind a server-version probe.

Files Changed:
- neo4j-cli/query/connect.go (drop txType param + txMetadata body; add
  doc comment explaining deferral and min server version)
- neo4j-cli/query/run.go (drop "user-direct" arg)
- neo4j-cli/query/schema.go (drop "schema" arg from all 6 runStatement
  calls)
- neo4j-cli/query/connect_test.go (drop TestRunStatement_SchemaTxType;
  drop txMetadata-equality assertion in TestRunStatement_HappyPath and
  replace with assert.NotContains(...) to lock in the deferral; drop
  txType arg from every test runStatement call)
- .changes/unreleased/neo4j-cli-Minor-20260505-130000.yaml (new — User-
  Agent only)
- .plans/prd-query-tx-metadata-user-agent.md (rewrite Overview / Goals /
  Non-Goals / Requirements / Acceptance Criteria to reflect scope cut)
- .plans/tasks-query-tx-metadata-user-agent.yml (rewrite task-003 to
  match the actual work; mark completed)

Key Decisions:
- Drop txMetadata entirely rather than gate it behind a server-version
  probe in this PR. Reason: keeps this change small and ships the safe
  half (User-Agent) immediately. A follow-up issue can introduce the
  probe + re-add the field once Neo4j 2026.04 is more common.
- Lock in the deferral with assert.NotContains(gotBody, "txMetadata") in
  the happy-path test, so a future accidental re-add fails loudly until
  whoever does it also wires up the version gate.
- Keep the userAgent field, resolveConn population, and User-Agent
  assertion unchanged — that work from task-001 / task-002 is the
  shippable half.
