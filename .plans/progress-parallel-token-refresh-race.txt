TASK-004: Add disk re-read optimization to getToken before the HTTP refresh call
Date: 2026-05-15T00:00:00Z
================================================================================

Summary:
Added a best-effort disk re-read path in getToken (neo4j-cli/aura/internal/api/token.go)
between the in-memory HasValidAccessToken() check and the HTTP token refresh. If
ReloadAuraCredential finds a valid token on disk (written by another process), it is
synced into memory via SyncCredential and returned immediately — no HTTP request is made.
If the reload fails or the disk token is also expired, the existing HTTP path is unchanged.

Files Changed:
- neo4j-cli/aura/internal/api/token.go (modified — 5-line disk re-read block inserted)
- neo4j-cli/aura/internal/api/token_test.go (created — TestGetToken_DiskReread)

Key Decisions:
- Reuses cfg.Aura.Fs() (the same afero.Fs used by the rest of the config stack) so the
  disk re-read works with any afero backend, including the MemMapFs used in tests.
- cfg.Credentials.FilePath() accessor (added in task-003) keeps getToken free of internal
  credentials state.
- Test overwrites credentials.json on the MemMapFs after Config construction to simulate
  a concurrent write by another process; asserts tokenEndpointCalled remains false.
- Test also asserts in-memory SyncCredential was called (AccessToken and TokenExpiry match
  the fresh disk values).
- No new imports in token.go — credentials package was already imported.

Gates: make test PASS, make fmt-check PASS, make lint PASS (0 issues).

TASK-003: Add Credentials.FilePath() accessor and ReloadAuraCredential helper
Date: 2026-05-15T00:00:00Z
================================================================================

Summary:
Added three new public API additions to the credentials package to support the
parallel token refresh race fix. FilePath() exposes the private filePath field
so callers (specifically getToken in task-004) can pass the path without
accessing internal state. ReloadAuraCredential reads credentials.json from disk
via afero and returns the named AuraCredential or nil,false on any error without
panicking. SyncCredential updates in-memory AccessToken/TokenExpiry without
calling onUpdate (no disk write), for use after a successful disk-based token
reuse.

Files Changed:
- common/clicfg/credentials/credentials.go (modified — added FilePath() accessor)
- common/clicfg/credentials/aura.go (modified — added SyncCredential method)
- common/clicfg/credentials/reload.go (created — ReloadAuraCredential function)
- common/clicfg/credentials/reload_test.go (created — unit tests for all three additions)

Key Decisions:
- ReloadAuraCredential uses fileutils.ReadFileSafe (returns empty slice on missing
  file) rather than direct afero.ReadFile to stay consistent with existing patterns
  and avoid panics on ErrNotExist.
- SyncCredential is silent no-op when the credential name is not found, which avoids
  any panic when called from a racing goroutine where the in-memory state may differ.
- Test helpers (credentialsPath, writeCredsJSON, freshToken) placed in reload_test.go;
  should move to a helpers_test.go if other test files in this package need them later.
- FilePath test uses testfs.GetTestFs so no real FS is touched on developer machines
  that have real Aura credentials stored.

TASK-001: Implement cross-platform advisory file lock helpers in fileutils
Date: 2026-05-15T00:00:00Z
================================================================================

Summary:
Added two build-tag-separated lock helper files to common/clicfg/fileutils/ and
wired acquireLock into writeFileAtomic so parallel writers are serialised at the
OS level. Also added *.lock to .gitignore so lock files created during make test
(e.g. typeDefs.graphql.lock) are not tracked as untracked files.

Files Changed:
- common/clicfg/fileutils/lock_unix.go (created — acquireLock via unix.Flock(LOCK_EX), !windows build tag)
- common/clicfg/fileutils/lock_windows.go (created — acquireLock via windows.LockFileEx, windows build tag)
- common/clicfg/fileutils/fileutils.go (modified — acquireLock called at start of writeFileAtomic, release deferred)
- .gitignore (modified — appended *.lock pattern)

Key Decisions:
- acquireLock uses os.OpenFile (not afero) so it works regardless of the afero.Fs
  implementation passed to WriteFile; the lock file is a real OS file.
- Lock file is never deleted; OS releases the flock/LockFileEx on close, so the
  file can be safely left behind (idiomatic for advisory locks).
- MkdirAll called inside acquireLock to ensure the parent directory exists before
  opening the lock file, matching the same pattern as writeFileAtomic itself.
- acquireLock wired into writeFileAtomic (not exported) keeps the locking
  transparent to callers; lint required it to be used in the same task.

Gates: make test PASS, make fmt-check PASS, make lint PASS (0 issues).
