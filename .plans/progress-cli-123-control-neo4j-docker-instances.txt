## PR description draft

Title: `feat(cli): add 'docker' command tree for local Neo4j containers (CLI-123)`

Linear: [CLI-123](https://linear.app/neo4j/issue/CLI-123/control-neo4j-docker-instances)

## Summary

Adds a `neo4j-cli docker` command tree for spinning up, inspecting, and tearing down local Neo4j containers via the host `docker` CLI. Containers carry an `org.neo4j.cli.managed=true` label (plus per-container metadata labels) so Docker itself is the source of truth — no separate state file under `cli/`. The flow is symmetric with `aura instance` so muscle memory carries over (`--name`, `--wait`, `--rw`, `--format`), and the resulting dbms credential drops straight into `neo4j-cli query --credential <name>`.

Shells out to the `docker` binary via `os/exec` — no Docker Go SDK dependency. Reuses the already-vendored `neo4j-go-driver/v6` from `query/` for Bolt readiness probes. Adds one new external dep: `golang.org/x/term` for TTY detection on `delete`'s confirmation prompt.

## Commands

| Command | Purpose | Write? |
|---|---|---|
| `docker create --name <s> [flags]` | Pull image, `docker run -d`, optionally store a dbms credential, optionally wait for Bolt | yes (`--rw`) |
| `docker list` | List containers with `org.neo4j.cli.managed=true` | no |
| `docker get <name>` | Render one managed container's details (name/status/edition/version/ports/uri/image/ephemeral) | no |
| `docker start <name> [--wait]` | `docker start` a stopped container; optional Bolt-ready wait | yes (`--rw`) |
| `docker stop <name> [--wait]` | `docker stop`; optional poll until exited | yes (`--rw`) |
| `docker delete <name> [--force]` | `docker rm -f` + remove the matching dbms credential | yes (`--rw`) |

All write commands respect the existing `--rw` write gate. All read commands accept `--format json|table|toon` (inherited from root). Every leaf has a flush-left `Example:` block that satisfies `TestAllLeafCommands_HaveExamples`.

### `docker create` flags

| Flag | Default | Behaviour |
|---|---|---|
| `--name` | *required* | Container name + dbms credential name. Auto-suffixed (`-1`, `-2`, …) on collision with any existing container OR stored credential; chosen name is echoed to stderr. |
| `--version` | `latest` | Maps to image tag. Community: `neo4j:<version>`. Enterprise versioned: `neo4j:<version>-enterprise`. Enterprise + default `latest`: bare `neo4j:enterprise` (Docker Hub does NOT publish `neo4j:latest-enterprise`). |
| `--edition` | `enterprise` | Validated against `community` / `enterprise`. |
| `--accept-license` | `false` | Enterprise only. Default passes `NEO4J_ACCEPT_LICENSE_AGREEMENT=eval`; this flag upgrades it to `yes`. No-op for community. |
| `--bolt-port` | `7687` | Pre-flight `net.Listen` check before any `docker run` so a port clash never leaves a half-created container behind. |
| `--http-port` | `7474` | Same pre-flight. `--bolt-port == --http-port` errors out before either check. |
| `--password` | random 16-byte (base64 URL-safe) | Generated via `crypto/rand` when omitted. Surfaced in `create`'s standard output. |
| `--no-store-credential` | `false` | Container still runs; skip persisting a dbms credential. |
| `--ephemeral` | `false` | `docker run --rm`; skip credential persistence; emit a `.env` blob to stdout (or `--env-out-file`) instead of the standard table/JSON. Incompatible with the three volume flags. |
| `--env-out-file <path>` | unset | Only with `--ephemeral`. Writes the env blob to this path via a temp file + atomic rename (mode `0o600`); stdout stays silent so it can be piped. A pre-existing symlink at the path is replaced by a regular file (not followed). Name explicitly marks the write direction to disambiguate from `query --env <path>` which reads. |
| `--wait` | `false` | Block until Bolt accepts an authenticated session (60s fixed timeout). On timeout the container is left running; the message points at `docker logs <name>`. |
| `--data-dir <path>` | unset | Bind-mount this host directory at `/data` inside the container so the database survives `docker delete`. Empty default = no mount. `~` and env vars are expanded; missing directories are created at mode `0o755`. Incompatible with `--ephemeral`. |
| `--logs-dir <path>` | unset | Same as `--data-dir` but mounted at `/logs` for host-side log access. |
| `--import-dir <path>` | unset | Same as `--data-dir` but mounted at `/import` for `LOAD CSV` from host files. |

## Credentials handling

By default `docker create` persists a `DbmsCredential` with `name = <chosen container name>`, `username = neo4j`, `password = <generated or supplied>`, `database = neo4j`, `uri = neo4j://localhost:<bolt-port>`. First credential added becomes the default (existing `DbmsCredentials.Add` behaviour). `neo4j-cli query --credential <name>` then connects against the local container without any further setup.

- `--no-store-credential` skips persistence; the container runs with the generated password but no credential is stored. The password still appears in the rendered output.
- `--ephemeral` always skips credential persistence (it would outlive the container). Instead, an `.env` blob (`NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE`) is emitted — to stdout, or to `--env-out-file <path>` for `neo4j-cli query --env <path>`. Env var names match what `query --env` already consumes, no `query`-side changes needed. The asymmetric flag names (`--env-out-file` vs `--env`) make the read/write direction explicit.
- `docker delete` removes both the container AND the matching dbms credential. A missing credential is *not* an error (e.g. `--no-store-credential` was used at create time). No `--keep-credential` flag — by design, the credential is meaningless once the container is gone.
- `docker start --wait` does an authenticated Bolt handshake when a stored credential exists. When no credential is available (the `--no-store-credential` path, external credential management, or corrupt store), it falls back to a TCP-only probe with an explicit stderr announcement — weaker (port-open != Bolt-ready) but strictly better than failing the wait.

> **Operator note**: the generated password is part of `create`'s standard output. Redirects (`> file`) and pipes (`| tee`, `| jq`) capture it. Pass `--password <s>` to choose your own, or `--no-store-credential` for neither stored nor rendered persistence (the container still uses a generated password internally).

## State model

Docker is the source of truth. Every managed container carries:

- `org.neo4j.cli.managed=true`
- `org.neo4j.cli.edition=<community|enterprise>`
- `org.neo4j.cli.version=<tag>`
- `org.neo4j.cli.bolt-port=<int>`
- `org.neo4j.cli.http-port=<int>`
- `org.neo4j.cli.ephemeral=<true|false>`

`list` filters on the managed label both daemon-side (`--filter`) and in Go (defensive against fakes that don't honour daemon-side filters). `get`/`start`/`stop`/`delete` Inspect first and refuse anything without the managed label — `neo4j-cli docker` never touches a container it didn't create.

## Security

- **Password generation**: `crypto/rand`, 16 bytes → base64 URL-safe → 22 chars. Injectable `randSource` seam for deterministic tests.
- **Argv redaction**: `docker run` errors are surfaced via `redactArgs(args)` which masks any `<LHS>=<value>` element where the uppercase-folded LHS contains `AUTH` or `PASSWORD`. The exec argv passed to `exec.CommandContext` is unchanged — redaction is only applied to the user-facing error string so a failed `docker run` never leaks `NEO4J_AUTH=neo4j/<password>` to terminals or CI logs.
- **`--env-out-file` writes**: temp file (`afero.TempFile` with random suffix) in the same directory, `chmod 0o600` while we still own the temp, then `Rename` over the final path. Closes the symlink-follow + chmod-TOCTOU windows the naive `OpenFile|Chmod` pattern had. A pre-existing symlink at `--env-out-file <path>` is replaced by a regular file (operator-visible behaviour change, documented).
- **`Inspect` error classification**: a typed `docker.ErrNotFound` sentinel distinguishes "container does not exist" (substring `"No such "` in docker stderr — stable across Docker versions for 7+ years) from operational failures (daemon down, socket permission denied, rootless misconfig). Leaves switch on `errors.Is(err, ErrNotFound)` → unknown-name; everything else propagates with the docker stderr verbatim so operators see what actually broke.
- **`exec.CommandContext` with discrete argv**: no shell invocation, no `sh -c`. Container names, label values, env values all travel as separate argv elements.
- **TTY confirmation on `delete`**: TTY callers without `--force` see `Delete container <name> and its dbms credential? [y/N]`; non-TTY callers must pass `--force` or the command errors (no silent destructive ops in scripts).
